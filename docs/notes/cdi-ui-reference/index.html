My read

Cockpit + Editorial is the pair worth carrying forward. Cockpit is the in-app working surface (tabbed, cleanest seam, best fit for the renderer → unified dashboard path); Editorial is the print/PDF deliverable. Triage's action-first ordering is a mode worth folding into Cockpit's CDI tab. Dashboard is the right north-star for the eventual all-cases view but isn't the per-case template.

All four are equally Electron-ready (10/10 self-containment). Pick on layout philosophy, not plumbing.

Cross-cutting — surfaced by building these (fix at the engine, not the HTML)

  • "Billed 99215" is not a structured field. Every variant had to hardcode or regex-infer it from the note's .KS15 placeholder / prose. em-score should emit a structured billed_em_code (parsed from the note) so the downcode story is data-driven, not inferred — this is the single change that makes all four templates fully case-agnostic.
  • Cross-engine disagreement, unreconciled. em-score scores Data = Straightforward; CDI flag-004 says Data = Low. Both render faithfully, so a reader sees two answers. The two E·M-touching engines need one source of truth (ties to the review's reimbursement_impact finding).
  • Date drift. generated_at is model-stamped midnight-Z → the dashboard renders "Jun 11" in any US timezone. The app should stamp real local time post-run (and the renderer should format date-only, not via toLocaleDateString on a Z-instant).
