# Add `gpt-5.6-luna` SOAP note-generation provider (OpenAI)

**Owner:** sr · **Date:** 2026-07-21 · **Branch:** `feature/gpt-5.6-luna`

## Context

A 27-run bake-off validated OpenAI's **gpt-5.6-luna** as a SOAP note-generation model. We want it
available as an **opt-in, selectable** note-gen option in the recording-app, alongside the existing
Anthropic (API + agentic) and Gemini providers. The default (`sonnet-4-6-api`) is **unchanged** — this
only adds a new dropdown choice; the rollout / default-flip is a later decision.

luna talks to the **real OpenAI endpoint**, which differs from Gemini's OpenAI-compat endpoint in two
load-bearing ways (both empirically validated by the bake-off):

- body must use `max_completion_tokens` — the gpt-5 family **rejects** `max_tokens`.
- body must pin the lowest reasoning the model accepts — higher effort measurably degraded notes
  (the plan leaked into the HPI). Effort is never exposed as a setting. **Correction (2026-07-22):** the
  handoff called for `reasoning_effort: "minimal"`, but the live API rejects `minimal` for this model
  (HTTP 400; supported: `none`/`low`/`medium`/`high`/`xhigh`) — pinned to `"low"` instead (closest to
  the intended minimal; `"none"` avoided as it's documented to be silently ignored alongside
  `max_completion_tokens` on some GPT-5 versions). See the DECISIONS 2026-07-22 addendum.

The single-call prompt contract (skill-as-system, §2.3 user layout, last-line JSON manifest) and
`splitNoteAndManifest` work **unmodified** — luna parsed/emitted manifests correctly in every run,
including multi-patient detection manifests (the existing detect→fan-out path handles those).

**Scope:** recording-app only. pa-scribe (the separate TypeScript repo) is out of scope.

### Handoff details reconciled against the actual code
- Keys route through `appCtx.secrets.get/setGeminiKey()` (a `.env`-backed secrets store), **not** raw
  `.env` reads in `config.js` — we mirror the secrets-accessor pattern.
- The SOAP-model `<select>` is **hardcoded** in `renderer/index.html` (the sandboxed renderer can't
  import `modelOptions.js`), so the new option is added by hand — it does not auto-render.
- There is a **second** provider ternary the handoff didn't mention — `src/jobs/prechartApi.js`
  (edit-note API path) — which also needs an OpenAI branch, else picking luna breaks pre-chart.
- Usage/cost: the provider emits `rawUsage` in the **Anthropic-shaped keys** `calcCost`/
  `normalizeApiUsage` already expect (as `geminiApiProvider` does), so only a `PRICE_TABLE` row is
  needed — no fork of the usage functions.

## Changes (as implemented)

- **New provider** — `src/llm/openaiApiProvider.js`, cloned from `geminiApiProvider.js`. Endpoint
  `https://api.openai.com/v1/chat/completions`, `Authorization: Bearer`. Body `max_completion_tokens`
  + `reasoning_effort: 'minimal'`. Usage → `{ input_tokens = prompt_tokens (incl. cached),
  output_tokens = completion_tokens (incl. reasoning — not double-counted),
  cache_read_input_tokens = prompt_tokens_details.cached_tokens }`; `reasoning_tokens` logged only.
- **Registry** — `src/llm/modelOptions.js`: add `'gpt-5.6-luna': { provider:'openai',
  model:'gpt-5.6-luna' }`. `DEFAULT_OPTION_ID` unchanged. `resolveCliModel` already falls back to the
  default Anthropic model for non-`api`/`cli` providers, so the post-SOAP engines + CLI prechart stay
  on `claude-sonnet-4-6` — no change.
- **Pricing** — `src/llm/pricing.js`: `PRICE_TABLE['gpt-5.6-luna'] = { in:1, out:6, cacheRead:0.10,
  cacheWrite:0 }` (keyed by the model string). No changes to `calcCost`/`normalizeApiUsage`.
- **Secrets / wiring** — `config/secrets.js` `get/setOpenAiKey()` (`OPENAI_API_KEY`);
  `context/appContext.js` instantiates `ctx.openai`.
- **`main.js`** — SOAP provider branch in `spawnSoapGeneration` (`opt.provider === 'openai'` →
  `ctx.openai`, `'OpenAI'`); `validateOpenAiKey` (GET `/v1/models`, Bearer); the two auth/rate-limit
  key-name ternaries extended to `'OPENAI_API_KEY'`; `validateOpenAiKey` added to the deps bag.
- **`src/jobs/prechartApi.js`** — provider + providerName + keyEnvName ternaries gain the `'openai'`/
  `'OpenAI'` branch.
- **IPC / preload / renderer** — `GET_OPENAI_KEY`/`SAVE_OPENAI_KEY` channels, `get/save-openai-key`
  config handlers, `preload.getOpenAiKey/saveOpenAiKey`, an OpenAI key field + a "GPT-5.6 Luna"
  dropdown option in `renderer/index.html` + `renderer/views/settingsView.js`.
- **DB** — none (`model_used` is free text).
- **Docs** — CLAUDE.md (settings/`.env`/models), ARCHITECTURE.md (provider table), DECISIONS.md
  (dated entry).
